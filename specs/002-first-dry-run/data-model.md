# Data model: Fifteen minutes to a first dry run

**Feature**: [spec.md](spec.md) | **Decisions**: [research.md](research.md)

No record or field of the system's configuration changes. What this
feature adds is a page, the script that runs it, the CI job that runs
the script, and four messages. The entities below are the spec's Key
Entities, with the fields and rules the plan gives them.

## The quickstart page

| Field | Value | Rule |
| --- | --- | --- |
| Path | `docs/QUICKSTART.md` | One page (FR-001); the only place its steps are written (FR-015) |
| Covers | macOS and Linux, x86_64 and arm64 | Stated at the top (FR-009); Windows named as not covered |
| Prerequisites | A table between two marker comments | Generated by `scripts/quickstart prerequisites --write` (R11); four or fewer under the spec as written, five under D1's default |
| Commands | Every line of every `sh` block, in page order | Ten or fewer (FR-008); runnable as written, nothing to fill in (FR-003) |
| Network | Which commands need it, which is slow | One short section (FR-009, R16) |
| After the run | What was produced, where, that nothing was applied, what the machine keeps | A few sentences after the last box (FR-007) |
| Next | Three links: a first real local run, the cloud starters, a team's own repository | The page's end (FR-008, R13) |

The format the runner reads is in
[contracts/quickstart-page.md](contracts/quickstart-page.md).

## The example configuration

| Field | Value | Rule |
| --- | --- | --- |
| Starter | `standard-docker` | The only starter that needs no account (the spec's Assumptions) |
| Written by | `cs-image-system init-config csis-quickstart --from standard-docker` | Into `csis-quickstart` under the reader's directory |
| Placeholders | `REPLACE-ME` values as the starter ships them | Validate and dry-run as written (FR-006; read, R5) |
| Encrypted values | None | No key is read; the committed test key is named on the page as unused (R5) |
| Emission | `csis-quickstart/generated/` and `csis-quickstart/meta-state/` | Written by the dry run; nothing applied, nothing committed |
| Left on the machine | `almalinux:10` in the daemon's store; the packer plugins | Named on the page with the command that removes the image (R16) |

## Prerequisites

| Tool | Floor | Source of the floor | Present on |
| --- | --- | --- | --- |
| uv | the oldest release the job passes on, from 0.8.0 (R11) | a constant in `scripts/quickstart` | installed by the reader |
| Docker: a daemon that answers and its CLI | CLI `>=24` | the starter's `cfg/executables.yml` | installed by the reader (Docker Desktop, OrbStack, colima, Docker Engine) |
| OpenTofu | `>1,<2` | the same | installed by the reader |
| Packer | `>=1.14` | the same | installed by the reader |
| bash | `>=5` | the same | Linux as shipped; macOS from a package manager (D1) |

`ansible-playbook` (`>=2.16`, the same source) is not a prerequisite: the
page's second command installs it with uv.

## The quickstart run (one run of the page)

| Field | Meaning |
| --- | --- |
| Packages | The wheels this commit builds, named to uv by `UV_OVERRIDE` (R8); the index only for third-party dependencies |
| Tool directory | A temporary `UV_TOOL_DIR` and `UV_TOOL_BIN_DIR`, never your own (R8) |
| Working directory | A temporary directory made by the runner; the page writes `csis-quickstart` into it |
| Boxes | `K` boxes, each with its commands; one shared bash session |
| Per box | `ran and succeeded`, `failed at <command> (exit N)` or `did not run` |
| Version check | After command 1, `cs-image-system --version` names the built version, or the run fails |
| Time | Each box's seconds and the page's total; limit 900 seconds on the first pass (R10) |
| Passes | Two in the CI job (story 1 scenario 5); one in the local recipe unless asked for two |
| Verdict | `passed` only when every command of every box ran and succeeded, the commands were ten or fewer, and the time was within the limit |

## The quickstart job

| Field | Value |
| --- | --- |
| Workflow | [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml), job `quickstart`, replacing `docker-install` (R9) |
| Runs on | Every push and pull request; no condition, no secret |
| Machine | A container from the stock `ubuntu:24.04` image, the host's docker socket mounted (R7) |
| Setup | The prerequisites at their floors (`just quickstart-prepare`), timed and reported apart from the page |
| Steps | `just test-quickstart` with two passes; `scripts/quickstart prerequisites --check` |
| Gates | `publish` needs it (R8) |
| Record | The runner's time lines, written to the job summary (FR-012) |

## State of a release with respect to the page

```text
a push or pull request   the job runs the page against the commit's wheels       publish cannot run without it
just release (local)     test-quickstart runs against the bumped tree's wheels    before any upload, both indexes
                         on your local machine (macOS)
full-test                test-quickstart is a leg that never reports SKIPPED
a final release          publish-starters regenerates the five template repositories with the corrected READMEs
```
